Time Manager lets employees clock in and out, managers run teams and follow KPIs, and admins (general managers) run the whole company. The generated API reference site (`/openapi`) lists every schema; this page states the rules behind them.

All timestamps are epoch milliseconds (UTC). Times of day (`work_start`, `work_end`) are `HH:MM` strings interpreted in the company timezone `APP_TIMEZONE` (default `Europe/Paris`). Every response uses the envelope `{ data, event, timestamp }` and lists return `data: { items, more, next, total }`.

## Roles

| Role | Can |
| --- | --- |
| `employee` | Clock in and out, see and edit their own profile, see their own clocks and reports, see teams they belong to |
| `manager` | Everything an employee can, plus create employees, create teams they manage, manage members of those teams, and see and correct clocks and reports of members of those teams |
| `admin` | Everything, on every user, team and clock |

A managed user is a user who belongs to at least one non-archived team whose `manager_id` is the actor. See [Roles and scopes](/docs/engineering/roles-and-scopes).

## Users

Mounted at `/v1/users`, tag `users`.

Entity: `id`, `object: 'user'`, `email`, `first_name`, `last_name`, `phone_number`, `role`, `created_at`, `updated_at`, `archived_at`. List filters add `team_id` (members of that team). There is no public signup: users are created through `POST /v1/users/new` by a manager or admin.

## Teams

Mounted at `/v1/teams`, tag `teams`, scopes `teams:read` and `teams:manage`. Tables: `teams` and `team_members`.

Entity `Team`: `id`, `object: 'team'`, `name` (1 to 100 characters), `description` (null or up to 500), `manager_id`, `member_count`, `weekly_hours_target` (1 to 80, default 35), `work_start` (default `09:00`), `work_end` (default `17:00`), `created_at`, `updated_at`, `archived_at`.

| Endpoint | Body or params | Returns | Who |
| --- | --- | --- | --- |
| `POST /new` | `{ name, description?, manager_id?, weekly_hours_target?, work_start?, work_end? }` | `Team` | Admin (any `manager_id`, which must be a manager or admin user). Manager (`manager_id` forced to self). |
| `POST /list` | `{ ids?, manager_id?, member_id?, archived?, created_after?, created_before?, cursor?, limit?, order? }` | page of `Team` | Admin: all. Manager: teams they manage or belong to. Employee: teams they belong to. |
| `GET /:id` | | `Team` | Same visibility as list |
| `PATCH /` | `{ ids, data: { name?, description?, manager_id?, weekly_hours_target?, work_start?, work_end? } }` | `{ success, updated, failed }` | Admin. Manager on teams they manage, without `manager_id`. |
| `POST /:id/archive`, `POST /:id/restore` | | `Team` | Admin. Manager on teams they manage. |
| `DELETE /` | `{ ids }` | `{ success, deleted, failed }` | Admin |
| `POST /:id/members/add` | `{ user_ids }` (up to 100) | `{ success, added, failed }` | Admin. Manager on teams they manage, employees only. |
| `POST /:id/members/remove` | `{ user_ids }` | `{ success, removed, failed }` | Admin. Manager on teams they manage. |
| `POST /:id/members/list` | `{ cursor?, limit?, order? }` | page of `User` | Anyone who can see the team |

`work_end` must be after `work_start`. Both match `^([01]\d|2[0-3]):[0-5]\d$`.

## Clocks

Mounted at `/v1/clocks`, tag `clocks`, scopes `clocks:read`, `clocks:write` and `clocks:manage`. Table: `clocks`. A user has at most one open clock (no `clocked_out_at`), enforced by a partial unique index.

Entity `Clock`: `id`, `object: 'clock'`, `user_id`, `clocked_in_at`, `clocked_out_at` (null while open), `duration_ms` (null while open), `note` (null or up to 500), `source` (`clock` or `manual`), `created_at`, `updated_at`.

| Endpoint | Body or params | Returns | Who |
| --- | --- | --- | --- |
| `POST /in` | `{ note? }` | open `Clock` | Self. `409 clock.conflict` if already clocked in. |
| `POST /out` | `{ note? }` | closed `Clock` | Self. `409 clock.conflict` if not clocked in. |
| `GET /current` | | `{ clock: Clock or null }` | Self |
| `POST /new` | `{ user_id, clocked_in_at, clocked_out_at, note? }` (manual entry, `source: 'manual'`) | `Clock` | Manager for managed users. Admin. |
| `POST /list` | `{ user_ids?, from?, to?, open?, cursor?, limit?, order? }` (`from` and `to` bound `clocked_in_at`) | page of `Clock` | Employee: own only. Manager: self and managed users. Admin: all. |
| `GET /:id` | | `Clock` | Owner, manager of the owner, admin |
| `PATCH /` | `{ ids, data: { clocked_in_at?, clocked_out_at?, note? } }` | `{ success, updated, failed }` | Manager for managed users. Admin. |
| `DELETE /` | `{ ids }` | `{ success, deleted, failed }` | Manager for managed users. Admin. |

Rules: `clocked_out_at` is after `clocked_in_at`; no future timestamps; a single clock cannot exceed 24 hours; a manual or corrected clock must not overlap another clock of the same user (`409 clock.overlap`).

## Reports

Mounted at `/v1/reports`, tag `reports`, scope `reports:read`. Reports are read-only KPIs computed with SQL aggregation over clocks. The range `from` to `to` is in milliseconds and at most 366 days. `granularity` is `day`, `week` or `month`.

| Endpoint | Body | Returns | Who |
| --- | --- | --- | --- |
| `POST /user` | `{ user_id, from, to, granularity }` | `UserReport` | Self, manager of the user, admin |
| `POST /team` | `{ team_id, from, to, granularity }` | `TeamReport` | Manager of the team, admin |

`UserReport` is `{ object: 'user_report', user_id, from, to, granularity, kpis, series }` with a zero-filled series of `{ period_start, worked_ms, late }`. `TeamReport` is `{ object: 'team_report', team_id, from, to, granularity, kpis, series, members }`. KPI definitions are in the [data model](/docs/engineering/data-model#kpi-definitions).

## Audit

Every mutation writes an `audit_logs` entry through `logService.create`.
